EagleEye Payment Process & API Integration Flow

This document details the payment workflows and API integration points between the EagleEye application and our payment processor. We use the processor's API at two main stages in our application: account verification during agent onboarding and payout execution when an agent requests a withdrawal.


Integration Endpoints

1. Account Validation API
We call this endpoint to verify that the bank details provided by an agent are correct.
- Inputs: Bank Code, Account Number
- Outputs: Registered Account Name (or a validation error if the details are incorrect)

2. Payout / Transfer API
We call this endpoint to disburse earned funds from our corporate wallet to an agent's validated bank account.
- Inputs: Destination Bank Code, Destination Account Number, Destination Account Name, Payout Amount, and a unique Transaction Reference ID
- Outputs: Transaction Status (Success, Pending, Failed) and Transaction ID

3. Webhooks & Transaction Status Queries
We expose a webhook listener and use status query endpoints to track the final state of transfers, especially those processed asynchronously.


Detailed Workflows

Agent Account Registration and Validation (Onboarding)
When an agent sets up their payment destination in their settings, we perform the following steps to ensure accuracy:
1. The agent selects their bank and inputs their account number.
2. The EagleEye backend automatically sends a server-to-server request to the Account Validation API.
3. If the validation fails, the API returns an error, and we prompt the agent to correct their details.
4. If successful, the API returns the official registered account name.
5. We display this account name to the agent for visual verification.
6. Once the agent confirms, we save the Bank Code, Account Number, and the exact returned Account Name to our database. To prevent fraud, the agent cannot edit or override the account name returned by the API.


Agent Payout & Funds Disbursement Flow
When an agent requests to withdraw their earnings, the application processes the transaction using the following sequence:
1. The agent requests a payout amount from their dashboard.
2. The system checks the agent's available balance in our database. If the requested amount exceeds the balance, the transaction is rejected immediately.
3. If the balance is sufficient, we lock the requested amount to avoid double-spending.
4. The system retrieves the agent's saved bank details (which were validated during onboarding).
5. The EagleEye backend makes a secure API request to the Payout API with the validated details and the payout amount.
6. If the processor responds with an immediate success or failure, we update the transaction history and release/deduct the funds accordingly.
7. If the transfer is pending, we wait for a webhook update from the processor.
8. Once the processor updates the transfer state, it sends a webhook event to our callback URL. After validating the signature on the webhook, we finalize the transaction:
   - Success: The locked funds are permanently deducted.
   - Failure: The locked funds are returned to the agent's active balance, and we notify them of the failure.


Security and Control Measures

- Server-to-Server Calls: All API interactions are conducted securely from the EagleEye backend. API keys and secrets are never exposed on the front-end client.
- Locked Account Names: Agents cannot modify the registered account name manually. We only send payouts to the exact name verified by the bank verification API.
- Daily Reconciliation: We compare our local transaction ledger against the daily reports fetched from the payment processor to ensure all records match perfectly.
- Webhook Verification: Our webhook listener validates the signature headers from the processor to prevent fake callback notifications.
